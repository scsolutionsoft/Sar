# ผลตรวจพื้นที่ทำงานตามบทบาท — 26 กันยายน 2026

## สิ่งที่แก้ไข

- เพิ่มทางลัดหน้า Dashboard ตามบทบาท และเมนูงานที่รอดำเนินการรวมกิจกรรม/รางวัลตามสิทธิ์ของบัญชี
- เพิ่มตัวกรองสถานะและรายการที่ตนสร้าง เลือกฝ่ายในฟอร์มตามสิทธิ์การบันทึกจริง และซ่อนปุ่มสร้างเมื่อบัญชีไม่พร้อมสร้างรายการ
- บังคับตรวจบทบาทในบริการแก้ไข/สร้าง/เปลี่ยนสถานะ แม้ผู้ชมเคยเป็นเจ้าของรายการมาก่อน
- ผู้อ่านทั่วไปเห็นตัวเลือกบุคคลเฉพาะที่เกี่ยวข้องกับผลงานที่มีสิทธิ์อ่าน นักเรียนเห็นตัวเลือกของตนและรายงานผูกกับ StudentId จากบัญชีฝั่งเซิร์ฟเวอร์
- ป้องกันลบทะเบียนนักเรียนที่มีบัญชีผูกอยู่ แสดงบทบาทและฝ่ายบนหน้ารายชื่อผู้ใช้และส่วนหัวเว็บ
- ตรวจ security stamp ทุกคำขอที่เข้าสู่ระบบ เพื่อยกเลิกเซสชันเก่าทันทีหลังแก้สิทธิ์/รีเซ็ตรหัสผ่าน

## หลักฐานทดสอบ

- Build solution ผ่าน ไม่มี warnings/errors; unit tests ผ่าน 42 กรณี
- ตรวจ 9 บัญชี ครบ 8 บทบาท รวมเมนูหลัก 100 เส้นทางจากทุกบัญชี ทางลัดหน้าแรก ฟอร์มสร้างเอกสาร/แฟ้ม และหน้าจัดการตามบทบาท ผ่าน
- ตรวจทั้ง GET และ POST พร้อม CSRF token ไปยังฟังก์ชันที่ไม่มีสิทธิ์ ต้องตอบ 403 ผ่าน
- รายงาน PDF ของทุกบัญชีสร้างและอ่านจำนวนหน้าได้จริง ตรวจหน้าจอ 390px ไม่มีการล้นแนวนอน
- ตรวจนักเรียนสองบัญชี: เปลี่ยน StudentId/TeacherId ใน URL ก็ไม่เปลี่ยนเจ้าของรายงาน ตัวเลือกไม่แสดงทะเบียนผู้อื่น
- ทดสอบครูสร้างกิจกรรมและรางวัล อัปโหลดภาพและ PDF แล้วใช้บัญชี DepartmentAdmin, Approver, PRAdmin และ SuperAdmin ส่งงานต่อจริง ทั้งส่งตรวจ ส่งกลับ ตรวจ อนุมัติ เผยแพร่ เก็บถาวร คืนฉบับร่าง และลบ ผ่าน
- รายการข้ามฝ่ายไม่ปรากฏในคิวผู้ดูแลฝ่าย และส่งคำสั่งตรวจข้ามฝ่ายไม่ได้ ครูเผยแพร่ข้ามขั้นตอนไม่ได้ ประชาสัมพันธ์ลบฉบับร่างของครูไม่ได้
- Administrator สร้าง/แก้ไข/ลบข้อมูลพื้นฐานได้ แต่ลบนักเรียนที่ผูกบัญชีไม่ได้
- SuperAdmin สร้างบัญชีทดสอบชั่วคราว เปลี่ยน Teacher เป็น Viewer แล้วเซสชันเดิมถูกส่งกลับหน้าเข้าสู่ระบบทันที ผ่าน
- `UiChecks --pr --demo-pr` ผ่านด้วยบัญชี PRAdmin: จัดข่าว สร้าง/แก้ไข เลือก/คัดลอก/อัปโหลดภาพ ขนาด/ลำดับ ช่วงวันแสดง ป้องกันแก้ทับ ลบ และอ่านวารสาร/PDF
- `UiChecks --personal` ผ่านครบ 9 บัญชีหลังแก้สิทธิ์ รวมไฟล์ส่วนตัว การป้องกันอ่าน/เขียนข้ามบัญชี สร้าง/อัปโหลด/บันทึกรายงาน PDF แฟ้ม Infographic / Flipbook รวมหลักฐาน จำกัดหน้า และยกเลิก PDF เมื่อแก้เนื้อหา
- ไม่มี JavaScript page errors ข้อมูลและไฟล์ fixture ของรอบทดสอบถูกลบแล้ว บัญชีทดสอบเดิมและรหัสผ่านเดิมคงอยู่
- EF ตรวจไม่มี model changes ที่ขาด migration; Publish Release / win-x64 สำเร็จที่ `artifacts/publish` การตรวจนี้ทำบน localhost ยังไม่ได้ติดตั้งชุดใหม่บน IIS

ภาพหน้าจอแต่ละบัญชี: `artifacts/ui/roles/`  
วิธีใช้งาน: [ROLE-WORKSPACES.md](ROLE-WORKSPACES.md)

- แยกเมนูเป็นกรอบพื้นที่ทำงาน ผลงานโรงเรียน พื้นที่ส่วนตัว สื่อและรายงาน พร้อมข้อมูลพื้นฐาน/ดูแลระบบตามสิทธิ์ เพิ่มไอคอน SVG สีทั้งหัวหมวด รายการ และการ์ดทางลัด

- `UiChecks --personal --workflow-only` ผ่าน: นักเรียนสร้างและแก้แฟ้ม เพิ่มภาพ/หลักฐาน จัดลำดับ เปิด Flipbook ส่งออก PDF ตรวจจำนวนหน้า และป้องกันเขียนข้ามเจ้าของ
- Build ไม่มี warnings/errors, unit tests 42 กรณีผ่าน, Publish Release / win-x64 สำเร็จ ไม่มี JavaScript page errors และ fixture ถูกลบแล้ว

## จำกัดรางวัลและเกียรติบัตรตามนักเรียน — 27 กันยายน 2026

- จำกัดรายการ ค้นหา รายละเอียด หน้าแรก สถิติ รายงาน และไฟล์ตาม StudentId ที่ผูกกับบัญชี ต้องมีชื่อในผู้รับรางวัล Published; รางวัลกลุ่มไม่แสดงผู้รับนักเรียนคนอื่น
- เพิ่มผู้รับรายไฟล์ใน AwardCertificate และหน้ากำหนดผู้รับ/อัปโหลด ไฟล์เดิมที่ไม่ระบุผู้รับถูกซ่อนจากนักเรียน
- `UiChecks --student-awards` ผ่านด้วยนักเรียนสองบัญชีและ SuperAdmin: เปิดรายละเอียด/ไฟล์/ดาวน์โหลดข้ามคนไม่ได้ ปลอม StudentId ในรายงานไม่ได้ รายงานพิมพ์และ Excel ใช้ขอบเขตเดียวกัน วารสารรวมรางวัลไม่เปิดให้บัญชีนักเรียน
- ตรวจอัปโหลดและกำหนดผู้รับจริง รวมผู้รับนอกกลุ่มตอบ 400, RowVersion เก่าตอบ 409, นักเรียน POST แก้ผู้รับตอบ 403, ถอนชื่อจากรางวัลแล้วไฟล์ตอบ 404 และบัญชีที่ไม่ผูกทะเบียนไม่เห็นข้อมูล
- ไม่มี JavaScript page errors และลบ fixture ทั้งรางวัล วารสาร และไบนารีของรอบทดสอบแล้ว
- Build ไม่มี warnings/errors และ unit tests 49 กรณีผ่าน; migration เพิ่มผู้รับรายไฟล์นำไปใช้กับฐานข้อมูล Sar แล้ว
- วิธีใช้งานและขอบเขต: [STUDENT-AWARD-ACCESS.md](STUDENT-AWARD-ACCESS.md)

- Build ไม่มี warnings/errors, unit tests 49 กรณีผ่าน และ EF ไม่มี model changes ที่ขาด migration

## คลังภาพกิจกรรมและลิงก์คลาวด์ — 27 กันยายน 2026

- เพิ่มเมนูคลังภาพ `/Gallery` แสดงอัลบั้มตามกิจกรรมพร้อมค้นหาชื่อ รหัส และคำบรรยาย รวมภาพที่มีอยู่เดิม
- รูปอัปโหลดเก็บไบนารีและคำบรรยาย เปิดป๊อปอัปเดิม ลิงก์คลาวด์เก็บ URL/คำบรรยาย แสดงชื่อเว็บไซต์และเปิดแท็บใหม่โดยไม่ผ่านป๊อปอัป
- Migration `20260927034408_AddActivityGalleryLinksAndCaptions` ใช้กับฐานข้อมูล Sar แล้ว EF ไม่พบ model changes ที่ขาด migration
- `UiChecks --gallery` ผ่าน: ครูอัปโหลดสองภาพพร้อมคำบรรยาย ตรวจไบนารี SQL แก้คำบรรยายเฉพาะภาพ เปิดพรีวิวพร้อมคำบรรยาย เพิ่ม/แก้/ลบลิงก์ ทดสอบเปิดแท็บไป URL เดิมโดยจำลองหน้าปลายทาง และค้นหาจากคำบรรยาย
- ตรวจ URL ที่ไม่ใช่ HTTP/HTTPS ถูกปฏิเสธ คำบรรยาย HTML ไม่ถูกประมวลผล RowVersion เก่าตอบ 409 อัปโหลดหลายไฟล์ที่มีรูปเสียไม่บันทึกบางส่วน และครูแก้กิจกรรมของผู้อื่นไม่ได้
- นักเรียนเห็นคลังของกิจกรรมสาธารณะ แต่ไม่เห็นปุ่มแก้ไขและ GET/POST แก้ไขตอบ 403 กิจกรรมส่วนตัวและไฟล์ตอบ 404
- มือถือ 390px ไม่ล้น ไม่มี JavaScript page errors และลบข้อมูล/ไฟล์ชั่วคราวแล้ว ภาพตรวจอยู่ที่ `artifacts/ui/gallery/album-mobile.png`
- Build สำเร็จและ unit tests 62 กรณีผ่าน คู่มือ: [ACTIVITY-GALLERY.md](ACTIVITY-GALLERY.md)

## Slug อัตโนมัติและ Wizard ตามบทบาท — 27 กันยายน 2026

- ช่อง Slug เป็นแบบอ่านอย่างเดียว สร้างจากฝั่งเซิร์ฟเวอร์เมื่อบันทึกข่าวใหม่และตรวจชื่อซ้ำ คง Slug เดิมเมื่อแก้ไขข่าว และละเว้นค่าที่ปลอมส่งจากฟอร์ม
- เพิ่ม `/Help` และ `/Help/Wizard` พร้อมเมนูทุกบัญชีและทางลัดในหน้าภาพรวม/แฟ้มนักเรียน หัวข้อครอบคลุมเมนูและงานตามบทบาท รวมคลังภาพและการตั้งค่าโปรแกรม
- `UiChecks --help-wizard` ผ่านครบ 9 บัญชี: หัวข้อตรงสิทธิ์ หัวข้อที่ไม่มีสิทธิ์ตอบ 404 ขั้นตอนนอกช่วงตอบ 400 ก่อนหน้า/ถัดไป เปิดหน้าทำงานแท็บใหม่ อ่านต่อ อ่านครบ และเริ่มใหม่ทำงานได้
- ความคืบหน้าใช้คีย์แยกบัญชี/บทบาทใน localStorage ตรวจมือถือ 390px และการเดินขั้นตอนเมื่อปิด JavaScript ผ่าน ภาพอยู่ที่ `artifacts/ui/help/`
- ครูสร้างข่าวชื่อเดียวกันสองรายการโดยไม่กรอก Slug ได้ลิงก์ไม่ซ้ำ แก้ชื่อและปลอม Slug ใน POST ไม่เปลี่ยนลิงก์เดิม การคืนฟอร์มที่ข้อมูลไม่ครบแสดง Slug เดิมถูกต้อง และ URL ข่าวเปิดได้หลังเผยแพร่สาธารณะเท่านั้น
- ไม่มี JavaScript page errors ลบกิจกรรมชั่วคราวแล้ว Build สำเร็จ unit tests 62 กรณีผ่าน และไม่มี model changes ที่ต้องเพิ่ม migration
- คู่มือ: [HELP-WIZARD.md](HELP-WIZARD.md)
