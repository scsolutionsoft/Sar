# พื้นที่ทำงานและสิทธิ์แต่ละบทบาท

ทุกบทบาทมี [ผลงานของฉัน](PERSONAL-WORKS.md) สำหรับเพิ่มกิจกรรม รางวัล เกียรติบัตร และอัลบั้มภาพส่วนตัว พร้อมรูป/PDF และลิงก์คลาวด์ โดยเข้าถึงได้เฉพาะเจ้าของบัญชี

เข้า `/Dashboard` เพื่อดูทางลัดตามบทบาทและจำนวนงานที่ต้องทำ นักเรียนเข้าสู่ระบบแล้วเปิด `/Admissions` สำหรับจัดแฟ้มศึกษาต่อได้ทันที ส่วนหน้าภาพรวมเปิดได้จากเมนูทุกบัญชี

| บทบาท | หน้าที่หลัก | ขอบเขตข้อมูลโรงเรียน |
|---|---|---|
| SuperAdmin | ผู้ใช้และสิทธิ์ ข้อมูลพื้นฐาน ประวัติ และทุกขั้นตอนผลงาน | ทั้งโรงเรียน |
| Administrator | ข้อมูลพื้นฐาน ประวัติ ตรวจ อนุมัติ เผยแพร่ ข่าวและวารสาร | ทั้งโรงเรียน ไม่มีเมนูจัดการบัญชี |
| PRAdmin | เผยแพร่งานที่อนุมัติ จัดข่าวตามช่วงเวลา และวารสาร | อ่านผลงานโรงเรียน แก้ไขฉบับร่างที่ตนสร้าง |
| Approver | อนุมัติหรือส่งกลับรายการที่ตรวจแล้ว | อ่านผลงานโรงเรียน; เพิ่มรายการได้เมื่อกำหนดฝ่าย |
| DepartmentAdmin | ตรวจหรือส่งกลับรายการที่ส่งตรวจ และดูแลงานร่างของฝ่าย | ฝ่ายของตน งานที่ตนสร้าง และรายการสาธารณะ |
| Teacher | สร้างกิจกรรม รางวัล แนบไฟล์ แก้ไขงานร่าง และส่งตรวจ | งานที่ตนสร้างและรายการสาธารณะ |
| Viewer | อ่านข่าว ผลงาน วารสาร และรายงาน | เฉพาะรายการสาธารณะและข้อมูลที่ตนมีสิทธิ์อ่าน |
| Student | คลังหลักฐาน แฟ้มศึกษาต่อ Infographic / Flipbook / PDF | รายงานผูกนักเรียนในบัญชีของตน อ่านข่าวและวารสารสาธารณะได้ |

ทุกบทบาทใช้คลัง PDF ส่วนตัวได้ ส่วนแฟ้มยื่นเรียนต่อเปิดให้เฉพาะบทบาท Student บัญชีอื่นไม่มีเมนูและถูกปฏิเสธทุกหน้า/คำสั่งใน `/Admissions` รวมถึงไฟล์แฟ้มเดิมของตน ผู้ดูแลระบบไม่มีสิทธิ์เปิดเอกสารหรือแฟ้มส่วนตัวของบัญชีอื่นผ่านหน้าใช้งานและ URL ไฟล์

บัญชีนักเรียนไม่มีเมนูหรือทางลัด “แฟ้มผลงานโรงเรียน” และเปิด `/Portfolios` โดยตรงไม่ได้ ใช้แฟ้มยื่นเรียนต่อของตนที่ `/Admissions` และรายงานกิจกรรมของตนที่ `/Reports`

## งานที่รอดำเนินการ

เมนู `/Workflows` แสดงเฉพาะงานที่บัญชีปัจจุบันมีสิทธิ์ทำขั้นตอนถัดไป ทั้งกิจกรรมและรางวัล พร้อมลิงก์เปิดรายละเอียด:

1. ครูสร้างฉบับร่าง แนบภาพ/เอกสาร แล้วส่งตรวจ
2. ผู้ดูแลฝ่ายตรวจรายการของฝ่าย หรือส่งกลับแก้ไข
3. ผู้อนุมัติอนุมัติรายการที่ตรวจแล้ว หรือส่งกลับแก้ไข
4. ประชาสัมพันธ์เผยแพร่รายการที่อนุมัติแล้ว
5. ประชาสัมพันธ์เก็บถาวร ผู้ดูแลระบบคืนจากเก็บถาวรเป็นฉบับร่างได้

ผู้ดูแลระบบดำเนินการตามลำดับข้างต้นได้ทุกขั้นตอน ระบบป้องกันการข้ามขั้นตอนฝั่งเซิร์ฟเวอร์ รายการที่ส่งกลับอยู่ในคิวแก้ไขของเจ้าของและผู้ดูแลฝ่าย

หน้ากิจกรรมและรางวัลกรองสถานะ และเลือก “เฉพาะที่ฉันสร้าง” ได้ การแบ่งหน้ายังคงตัวกรองเดิม ฟอร์มสร้างของผู้ใช้ทั่วไปในกลุ่มผู้แก้ไขเลือกได้เฉพาะฝ่ายของบัญชี ผู้ดูแลและประชาสัมพันธ์เลือกได้ทุกฝ่าย

## การตั้งค่าบัญชี

- Teacher และ DepartmentAdmin ต้องกำหนดฝ่ายเพื่อให้สร้างและส่งต่องานได้
- Student ต้องเชื่อมกับทะเบียนนักเรียนหนึ่งคน ระบบไม่ให้ผูกทะเบียนซ้ำกับบัญชีอื่น และป้องกันการลบทะเบียนที่มีบัญชีอยู่
- เมื่อเปลี่ยนบทบาท รีเซ็ตรหัสผ่าน หรือแก้ไขบัญชีจากหน้าผู้ดูแล เซสชันเก่าถูกยกเลิกในคำขอถัดไป ผู้ใช้เข้าสู่ระบบใหม่เพื่อรับสิทธิ์ล่าสุด
- หน้าผู้ใช้แสดงบทบาท ฝ่าย และนักเรียนที่ผูกกับบัญชี เพื่อให้ตรวจการตั้งค่าได้โดยไม่ต้องเปิดทีละบัญชี
- รายงานนักเรียนบังคับรหัสนักเรียนจากบัญชีฝั่งเซิร์ฟเวอร์ แม้แก้ query string หรือส่งฟอร์มด้วยรหัสคนอื่น ผลงานโรงเรียนที่ยังไม่เปิดเผยแพร่ไม่ปรากฏในรายงานของนักเรียน เอกสารที่นักเรียนเพิ่มเองใช้เมนูคลัง PDF และแฟ้มยื่นเรียนต่อ

## ทดสอบซ้ำ

เปิดเว็บที่ `http://localhost:5093` แล้วใช้:

```powershell
dotnet test SchoolPortfolioPR.Tests
dotnet run --project SchoolPortfolioPR.UiChecks -- --roles
dotnet run --project SchoolPortfolioPR.UiChecks -- --personal
```

ชุด `--roles` ตรวจทุกบัญชีจริง เมนูและทางลัด ฟอร์มที่ใช้ได้/ใช้ไม่ได้ การส่ง POST ข้ามสิทธิ์ PDF และมือถือ รวมถึงสร้างข้อมูลชั่วคราวเพื่อส่งงานครู → ฝ่าย → ผู้อนุมัติ → ประชาสัมพันธ์ ทั้งกิจกรรมและรางวัล แล้วลบเฉพาะข้อมูลทดสอบรอบนั้น ภาพหน้าจอแต่ละบัญชีอยู่ที่ `artifacts/ui/roles/` บัญชีและรหัสผ่านอยู่ที่ `artifacts/private/TEST-ACCOUNTS.md`
